# Lumen v0.15.0 release candidate

This release focuses on native Kubernetes operations and reliable troubleshooting.

## Changes

- Removed the Copilot drawer, AI Assistant page, provider discovery, model calls,
  assistant-run commands, and AI entry points. Kubernetes inspection, incident
  reports, logs, and runbooks remain available without a model.
- Existing AI URLs open the workloads view in the corresponding context. Saved
  query text remains in the URL. Saved `ask-ai` runbook steps become manual
  checklist steps containing their existing notes and prompts.
- Existing local assistant history and preferences are retained, although the
  removed assistant UI no longer displays them. Loading a runbook does not
  rewrite its storage; normal edits persist the compatible representation.
- YAML editing requires a successful server dry-run of the current draft and
  target. Editing or changing targets invalidates the approval. Apply checks
  PATCH permission and no longer forcibly takes ownership of other managers'
  fields; ownership conflicts are surfaced for review.
- Shell starts honor the selected container and parsed command arguments. Tab
  identity follows the actual session, and fast commands are not started twice
  when the terminal mounts. Removed the inactive terminal Reset control.
- Log streams report connecting, live, retrying, ended, and error states;
  transient interruptions reconnect with bounded backoff and timestamp resume.
  Previous-container logs finish as one-shot reads.
- Refreshed compatible dependencies and replaced the license-dependent secret
  scanner with a checksum-pinned open-source Gitleaks binary.
- Release builds verify their exact commit through CI and remain drafts until
  reviewed. Required branch checks include disposable-cluster integration.

## Validation scope

Unit/component tests cover validation races, permissions, shell parameters and
log lifecycle. The isolated kind test calls Lumen's Rust apply/delete/access
functions against a real Kubernetes API, checking dry-run non-persistence,
namespace isolation and read-only RBAC. Its kubeconfig is temporary, and the
fixture cluster is deleted on exit. These checks do not substitute for desktop
end-to-end tests or installation tests on every supported operating system.

Before publication, complete macOS/Windows/Linux fresh-install and upgrade tests
and record signing/notarization status. Tauri updater signatures and operating
system code signatures serve different purposes; asset presence alone does not
prove either an install or update works.

## Known upstream dependency warnings

The dependency audit reports no vulnerabilities after the refresh. It still
reports 16 unmaintained transitive packages (primarily GTK3 and Unicode support)
and the `glib` 0.18.5 soundness advisory `RUSTSEC-2024-0429` through the Linux
Tauri stack. No audit ignore is added. Track these upstream requirements before
claiming a clean supply chain or general-availability Linux support.
