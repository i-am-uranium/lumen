# Lumen v0.16.0 — operator workflows

This release brings namespace-scoped browsing, connection recovery, and a
connected investigation workflow to Lumen's native Kubernetes workbench.
It also includes the native-core changes prepared in the unpublished
[v0.15.0 candidate](https://github.com/ravirann/lumen/blob/v0.16.0/docs/release/v0.15.0.md).

## Highlights

- Workloads and triage honor explicit namespace selection, remember it per
  context, and fall back to the kubeconfig default. Enter a known namespace
  when discovery is denied; successful results remain visible when other
  sources are unavailable.
- Connection diagnostics inspect kubeconfig and credential-tool availability
  without running credential tools. Guidance distinguishes authentication,
  TLS, network, and permission failures; retry refreshes both connection and
  local inspection results after external repairs.
- Investigate a triage issue through its failing container's current or
  retained previous logs, exact resource events, and owner/controller
  snapshots. Export the selected evidence with capture times and missing-source
  notes.
- Copilot and AI entry points are removed. Kubernetes inspection, incident
  reports, logs, and runbooks work without a model or hosted backend.

## Fixes and safeguards

- Both YAML editors require PATCH permission, successful server-side dry-run
  of the same draft, confirmation, and global read-only enforcement. Changes
  to the draft, target, or read-only mode retire prior validation.
- Windows `KUBECONFIG` drive letters and semicolon-separated source paths are
  handled correctly.
- Namespace requests wait for scope resolution; manual Refresh cannot bypass
  that gate. Late investigation and log results cannot cross selected targets.
- Shell execution respects the selected container and command arguments.
  Log streams expose lifecycle state and retry transient failures; retained
  previous-container logs finish as one-shot reads.

## Upgrade notes

- Users upgrading from v0.14.0 also receive the v0.15.0 native-core changes.
- Existing AI URLs open the workload view. Saved AI runbook steps become
  manual checklist steps; existing local assistant history/preferences are
  retained but no longer displayed.
- Namespace defaults now follow kubeconfig (or Kubernetes' `default` when
  omitted). Choose all namespaces explicitly when that is intended.

## Known limits

- Kubeconfig still uses the first source; multi-file merging is deferred.
- Investigation owner evidence is a current snapshot, not historical rollout
  causality. Event matching lacks UID correlation, so recreated same-name
  resources can include older events. The investigation links logs; reports do not embed log contents.
- Triage marks warning-stream availability and completeness as unverified:
  the native event protocol does not report watcher failures. Zero received
  warnings does not establish that none exist.
- The Rust audit retains 17 upstream warnings, including GTK3/Unicode
  maintenance warnings and the `glib` soundness advisory. No new audit ignores
  or dependency changes are introduced by this release bump.

## Downloads and release validation

The pipeline prepares Apple Silicon/Intel macOS DMGs, Linux AppImage/DEB/RPM,
Windows NSIS/MSI, updater signatures, and `latest.json` as draft assets. It
validates the exact release commit and the asset manifest before publication.

Platform signing, fresh installation, and upgrade/relaunch checks remain
publication gates in the [release checklist](https://github.com/ravirann/lumen/blob/v0.16.0/docs/release/RELEASE_CHECKLIST.md). Tauri
updater signatures do not establish macOS notarization or Windows Authenticode
signing. Treat unsigned builds as previews and record actual signing status
before publishing. Use the SHA-256 digests shown with the GitHub release assets
to check downloaded files.
